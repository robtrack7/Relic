# Surface patterns

## Application shell

A Saga opens directly to the **last Desk/Board working state** when safe.

Default desktop hierarchy:
- minimal left tool/navigation strip;
- main Desk/canvas;
- global Search in top frame;
- persistent/collapsible Librarian carriage on the right;
- focused entity surface may open between canvas and Librarian.

Keep durable navigation close to:

**Desk · Library · Sessions**

Do not restore a dashboard, Threads rail, Review inbox, Prepare rail and multiple mode switches simply because old specs had them.

## Desk

The Desk is home, not an empty-state form.

At rest support:
- immediate fragment creation;
- drag/drop/paste;
- Boards;
- multi-select and grouping;
- global search;
- Focus;
- lens switching;
- contextual Librarian invocation;
- undo/redo.

Status should inhabit the world rather than replace it. Example: after a session, a `Since last session` affordance can appear on the Desk without routing to a dashboard.

## First run

First run occurs **on the real Desk** and performs real worldbuilding.

Offer three conceptual entries without turning them into a wizard maze:
- Build with the Librarian;
- Bring your notes/sources;
- Start blank.

Preferred flow:
1. open an intentionally sparse Desk;
2. show ephemeral starter prompts/scraps rather than fake canon records;
3. Librarian carriage explains only enough to begin;
4. the GM writes/imports/speaks;
5. a living composition materializes beside the conversation;
6. Characters/Places/Threads/Events appear as Pencil where appropriate;
7. the GM edits/rearranges naturally;
8. deliberate settlement establishes initial claims and matures accepted objects;
9. the result remains exactly where the GM was already working.

Do not require a separate scaffold-review page if the emerging world itself can be the review surface.

Useful contracts preserved from older first-run work:
- resumable state;
- never lose typed/imported input;
- source/provenance survives;
- partial regeneration must preserve unrelated GM edits;
- model/network failure leaves the Desk/workshop intact;
- Start Blank is not punished.

## Library

Library is the exact/systematic index into the world.

Use it for:
- browse/filter by type/scope/state;
- archived material;
- sources/imports;
- exact management tasks;
- systematic Thread index;
- finding things when spatial context is irrelevant.

Library/Search retrieves an identity regardless of Board placement.

## Sessions / Prepare

Sessions is a durable lifecycle/history destination. Opening a planned/ready session produces **Prepare**, the same world arranged for tonight.

Prepare may contain:
- objective/opening;
- scenes/beats;
- active Threads;
- pinned World Objects;
- reminders/secrets;
- imagery/references;
- decisions/questions.

The Librarian may gather relevant material but should attach reasons/sources when non-obvious.

Prepare → Stage is narrowing, not copying/exporting. Preserve shared identity and repository lifecycle rules.

## Stage

Stage is Relic under severe attention constraint.

Prime rule: **every interaction is a glance, not a workflow.**

Keep on one live surface:
- session frame/state;
- smallest useful opening/agenda;
- active Threads;
- pinned Characters/Places/etc.;
- persistent fast Search;
- Capture;
- recording;
- Mark Moment;
- basic dice if in product scope;
- reduced Librarian access.

### Smallest useful result first

For lookup:
1. identity/name;
2. one or two live-useful facts;
3. source/session cue;
4. expand for depth.

### Capture and stubs

Capture first; classify later.

Quick Capture / improvised stub is normally **Pencil material** and remains persistent through Stage, Search, Desk and later Review.

Do not confuse maturity with truth:
- a Pencil Orin may already have an established `Orin is the locksmith` claim if the GM deliberately asserted it;
- raw captured text remains evidence until interpreted/settled.

Spoken words are not automatically authoring. Direct truth assertion needs a deliberate invocation/gesture.

### Offline/recovery

Preserve the useful old Stage contracts:
- local-first evidence/recording;
- durable intent before network send;
- explicit quiet states such as queued/syncing/failed/conflict/recovered;
- causal replay so End Session cannot outrun earlier evidence writes;
- no forced conflict-resolution workflow during play unless safety requires it.

### End Session

End Session is the seam into synthesis. Preserve deliberate confirmation, recovery/undo if the current lifecycle supports it, and safe ordering of evidence.

## Review

Primary review is the world under a **Since last session** delta.

Show changes where they live:
- new Pencil objects;
- matured/changed objects;
- event/history additions;
- Thread movement;
- changed relationships;
- proposed knowledge/claims;
- affected places;
- evidence/source disclosures.

Group by story/causal context before schema fields.

Use a compact completeness index only to answer:
- how many changes exist;
- what remains unseen;
- what remains unresolved;
- where the next item lives.

Correct a bad source signal once; dependent provisional interpretations may recompute. Conflicting settled claims stay visible for judgment.

## Chronicle / Relationships / Map

These are **Desk lenses**, not new silos. Read `temporal-chronicle.md` for Chronicle semantics.

Changing lens preserves selection/focus and should feel like the same world rearranging under different gravity.

## Mobile

Preserve workflow parity, not canvas parity.

Default mobile behavior:
- focused/stacked projection of current Board;
- beautiful animated movement between object depths;
- sheets for context and Librarian;
- full Search;
- history/Chronicle readable and navigable;
- full canvas remains accessible as a deliberate mode rather than default interaction.

Use Miro-like mobile canvas patterns as interaction precedent where useful, but do not shrink desktop controls into tiny handles.

Stage remains the strongest mobile-native surface.

## Accessibility

- Selection/Focus needs keyboard and screen-reader paths.
- Spatial relationships need ordered textual equivalents.
- Pencil/Ink cannot be color/line-style only.
- Truth/provenance must have textual/semantic labels.
- Motion cannot carry unique information.
- Stage controls need large targets and explicit state.
- Focus changes manage keyboard focus predictably.
