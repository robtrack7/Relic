# Relic MVP Gap Analysis

**Audit date:** 2026-07-20

**Authority:** `Relic Vault/00 - Start Here.md`, then active product, architecture, UX, and implementation notes.

**Implementation snapshot:** current working tree after the provider-backed transcription and transcript-review slice, followed by a full P0/P1/P2 status audit.

## How this audit was performed

This is an implementation audit, not a route inventory. Each item was checked against the active vault requirements, route loaders/actions, Supabase migrations and Edge Functions, explicit disabled/stub markers, automated tests, and the locally running authenticated application. `Complete` means the checked end-to-end behavior exists at the audited layer. `Partially complete` means a usable slice exists but one or more acceptance requirements do not. `Blocked` means the repository contains a contract or queue but an external/provider/runtime dependency still prevents the user workflow.

The strongest completed foundation is the scoped Postgres/RLS/RPC layer. The web manual spine is real but incomplete. Durable Stage audio now reaches a provider-backed transcription worker and a timestamp-preserving transcript review/retry surface. The largest remaining MVP risk is that backend *contracts* for synthesis and other AI tasks, embeddings, notifications, cleanup, and export can look finished while their provider delivery paths or web entry points remain absent. Hosted transcription still requires deployed secrets and a live LiteLLM smoke test; deterministic local provider mode does not close that operational gap.

## Immediate next workstream — Stage interaction reliability

This is the next bounded P0 slice because the confirmed focus bug interrupts ordinary Dice, Create, Note, and End interactions during a live session. It is narrower and lower-risk than opening the synthesis/provider workstream while the primary live surface is unreliable.

1. **Stabilize dialog lifecycle.** Make close/action callbacks stable so the one-second elapsed-time render cannot rerun focus initialization. Preserve Escape, backdrop close, focus trap, and focus return.
2. **Lock interaction regressions.** Add fake-timer/component coverage that types continuously for multiple clock ticks in Dice, Create, and Note; cover the two-step End flow as well.
3. **Prove Dice behavior.** Keep the existing Normal/Advantage/Disadvantage control visible when a d20 is selected, persist the selected mode, and cover normal plus pinned-dice execution.
4. **Prove Quick Create persistence.** Exercise NPC, Location, Item, Thread, Note, and Faction mappings through the scoped Stage actions; refresh Library data and assert the created record is visible with the correct type/stub semantics.
5. **Expose active Threads without changing the rail.** Add a compact, read-only active-Thread area in the existing Stage content hierarchy; do not introduce a sixth rail action.
6. **Apply restrained shell polish.** Bring the Stage top bar closer to the current visual direction without changing route hierarchy or the standalone wireframe's information architecture. Keep `GM Screen` for MVP; the requested `Rulebook` rename remains post-MVP.

**Exit gate:** the four target viewports retain their wireframe; focused tests cover uninterrupted typing, Dice modes, Quick Create→Library persistence, Threads, End/Undo, and keyboard/backdrop behavior; lint, web tests, build, and responsive Stage E2E pass.

**Workstream immediately after:** return to the post-session P0 path—pasted/manual evidence intake, `synthesize_session`, source-aware draft creation, and source-context navigation—then complete hosted LiteLLM/embedding smoke tests.

## Recommended execution order

1. Close Stage interaction reliability using the bounded workstream above.
2. Finish the now-started post-session loop: hosted transcription smoke, pasted/manual inputs, synthesis, source deep links, Approval Queue diff/edit/conflict.
3. Extend the Stage offline queue from durable audio to capture/stub/Mark/End and add the full airplane-mode regression.
4. Wire the already-specified AI runtime into New saga, Prep, creative tasks, and Relic Guide with quota/failure UX.
5. Complete account/Saga lifecycle, settings/retention/preferences, real export, and real notifications.
6. Resolve the mobile release gate, then either ship the responsive-web alpha explicitly or build the Expo client against the proven Stage contracts.
