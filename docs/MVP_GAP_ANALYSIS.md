# Relic MVP Gap Analysis

**Audit date:** 2026-08-04

**Authority:** `Relic Vault/00 - Start Here.md`, then active product, architecture, UX, and implementation notes.

**Implementation snapshot:** current working tree after Stage A1–B2, completed Phase C, manual-spine Packets D1–D4, D5 paste/text/Markdown Import Inbox intake, completed E1/E2 shared delivery, E3 Guide compatibility layer, E4 Session Prep AI, and deterministically complete E5.1-E5.2 profile-aware conversational Saga creation. Revised Phase E makes The Loom the universal conversational operating layer; E6 action-kernel work is immediate. `.docx` remains explicitly deferred behind the trusted extraction boundary; imported sources are not automatically enrolled.

## How this audit was performed

This is an implementation audit, not a route inventory. Each item was checked against the active vault requirements, route loaders/actions, Supabase migrations and Edge Functions, explicit disabled/stub markers, automated tests, and the locally running authenticated application. `Complete` means the checked end-to-end behavior exists at the audited layer. `Partially complete` means a usable slice exists but one or more acceptance requirements do not. `Blocked` means the repository contains a contract or queue but an external/provider/runtime dependency still prevents the user workflow.

The strongest completed foundation is the scoped Postgres/RLS/RPC layer. Durable Stage audio reaches a provider-backed transcription worker and a timestamp-preserving transcript review/retry surface. Validated synthesis results persist as one source-checked, idempotent pending batch, citations remain inspectable, and only explicit Approval Queue actions can move reviewed content into canon/audit. D1 proves real Saga Storage cleanup and database finalization; E1/E2 prove scoped retrieval and hosted delivery; E3 proves sourced conversation; E4 proves six cited Session Prep tasks; and E5.1-E5.2 prove a resumable, cost-disclosed Loom interview/scaffold/review flow with zero pre-commit product writes and asynchronous embedding enrollment only after explicit GM commit. The largest remaining MVP AI workflow risk is the E6-E10 typed operating layer, alongside real notification/export delivery.
