# Relic MVP Gap Analysis

**Audit date:** 2026-07-21

**Authority:** `Relic Vault/00 - Start Here.md`, then active product, architecture, UX, and implementation notes.

**Implementation snapshot:** current working tree after the provider-backed transcription/review slice, the Stage A1–A3 stabilization packets, the B1/B2 web offline-recovery milestone, and completed Phase C: manual evidence intake, synthesis orchestration, atomic source-aware drafts, source-context/citation-drift navigation, and the field-diff Approval Queue trust boundary.

## How this audit was performed

This is an implementation audit, not a route inventory. Each item was checked against the active vault requirements, route loaders/actions, Supabase migrations and Edge Functions, explicit disabled/stub markers, automated tests, and the locally running authenticated application. `Complete` means the checked end-to-end behavior exists at the audited layer. `Partially complete` means a usable slice exists but one or more acceptance requirements do not. `Blocked` means the repository contains a contract or queue but an external/provider/runtime dependency still prevents the user workflow.

The strongest completed foundation is the scoped Postgres/RLS/RPC layer. The web manual spine is real but incomplete. Durable Stage audio reaches a provider-backed transcription worker and a timestamp-preserving transcript review/retry surface. Validated synthesis results persist as one source-checked, idempotent pending batch, citations remain inspectable, and only explicit Approval Queue actions can move reviewed content into canon/audit. The largest remaining MVP risk is that hosted provider delivery, embeddings, notifications, cleanup, and export can look finished at the contract layer while their deployed or user-facing paths remain incomplete. Hosted transcription/synthesis still requires deployed secrets and a live LiteLLM smoke test; deterministic local fixtures do not close that operational gap.
