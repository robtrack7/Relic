# Relic MVP Gap Analysis

**Audit date:** 2026-07-21

**Authority:** `Relic Vault/00 - Start Here.md`, then active product, architecture, UX, and implementation notes.

**Implementation snapshot:** current working tree after Stage A1–B2, completed Phase C, manual-spine Packets D1–D4, D5 paste/text/Markdown Import Inbox intake, completed E1/E2 shared delivery, and locally complete but hosted-environment-gated E3 Relic Guide. `.docx` remains explicitly deferred behind the trusted extraction boundary; imported sources are not automatically enrolled.

## How this audit was performed

This is an implementation audit, not a route inventory. Each item was checked against the active vault requirements, route loaders/actions, Supabase migrations and Edge Functions, explicit disabled/stub markers, automated tests, and the locally running authenticated application. `Complete` means the checked end-to-end behavior exists at the audited layer. `Partially complete` means a usable slice exists but one or more acceptance requirements do not. `Blocked` means the repository contains a contract or queue but an external/provider/runtime dependency still prevents the user workflow.

The strongest completed foundation is the scoped Postgres/RLS/RPC layer. The web manual spine is real but incomplete. Durable Stage audio reaches a provider-backed transcription worker and a timestamp-preserving transcript review/retry surface. Validated synthesis results persist as one source-checked, idempotent pending batch, citations remain inspectable, and only explicit Approval Queue actions can move reviewed content into canon/audit. D1 additionally proves real Saga Storage cleanup and database finalization through the local worker. E1 proves deterministic/hosted embedding delivery and scoped hybrid retrieval; E2 proves real hosted transcription, record/query embeddings, one light and one deep registry task, exact-retry metering, controlled recovery, tenant isolation, zero canon writes, Vault-authenticated schedules, and payload-free operational evidence. The largest remaining MVP risks are wiring these shared contracts into the product AI surfaces beginning with E3, plus real notification/export delivery.
