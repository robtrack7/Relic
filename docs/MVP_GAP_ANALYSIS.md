# Relic MVP Gap Analysis

**Audit date:** 2026-07-20

**Authority:** `Relic Vault/00 - Start Here.md`, then active product, architecture, UX, and implementation notes.

**Implementation snapshot:** current working tree after the Stage evidence-path closeout.

## How this audit was performed

This is an implementation audit, not a route inventory. Each item was checked against the active vault requirements, route loaders/actions, Supabase migrations and Edge Functions, explicit disabled/stub markers, automated tests, and the locally running authenticated application. `Complete` means the checked end-to-end behavior exists at the audited layer. `Partially complete` means a usable slice exists but one or more acceptance requirements do not. `Blocked` means the repository contains a contract or queue but an external/provider/runtime dependency still prevents the user workflow.

The strongest completed foundation is the scoped Postgres/RLS/RPC layer: all 274 pgTAP tests pass. The web manual spine is real but incomplete. The web audio evidence path now reaches durable Storage and complete-set transcription enqueue; the largest remaining MVP risk is that backend *contracts* for AI, provider transcription, embeddings, notifications, cleanup, and export can look finished while their provider delivery paths or web entry points remain absent.

## Confirmed product decisions still required

These are questions, not implementation defects that should be silently guessed:

1. **Native mobile release gate:** Is the responsive web Stage sufficient for private MVP alpha, or does the active P0 commitment still require an Expo build before MVP?
2. **World/Saga switcher scope:** The active PRD requires switching, while the current shell renders three switcher buttons without behavior. Confirm whether one combined picker is acceptable for MVP.

## Recommended execution order

1. Make the post-session loop real: transcription provider, transcript review/edit, synthesis, source deep links, Approval Queue diff/edit/conflict.
2. Extend the Stage offline queue from durable audio to capture/stub/Mark/End and add the full airplane-mode regression.
3. Wire the already-specified AI runtime into New saga, Prep, creative tasks, and Relic Guide with quota/failure UX.
4. Complete account/Saga lifecycle, settings/retention/preferences, real export, and real notifications.
5. Resolve the mobile release gate, then either ship the responsive-web alpha explicitly or build the Expo client against the proven Stage contracts.
