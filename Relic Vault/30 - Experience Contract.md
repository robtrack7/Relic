# Experience Contract

## Shell and navigation

The Sanctum is the default authenticated home. Its web shell has independent Workspace, World, and Saga controls; Search; The Loom; global create; current-session/Review/usage state; account controls; and a rail for Home, Threads, Library, Prepare, Sessions, Review, Export, and Settings. Stage is contextual—not a default rail item—and is entered from Ready/Open Stage, the current session, deep links, resume, or Return to Stage.

The Stage is visually and operationally distinct: clean, dark, focused, and usable under time pressure. It presents session state, literal search, agenda, pinned content, notes/capture, recording consent/state, Mark Moment, basic system-neutral dice, End/undo, and bounded offline/reconnect feedback. A GM may invoke The Loom; the UI must never imply autonomous narration, silent mutation, background synthesis, or rules adjudication.

The Loom is named consistently in visible text. It is a collapsible sidecar/sheet or compatibility fallback page, preserves the GM's prompt/state across recoverable failure, distinguishes cited facts from proposals/insufficiency, and makes source, cost, authority, confirmation, receipt, failure, retry, and manual fallback inspectable. Search remains available when quota/provider work is unavailable.

## Core experience rules

- First run makes Start Blank available without AI. Build with AI and Bring Your Notes use a resumable workshop/review/explicit-commit boundary; no answer turn silently creates canon.
- Library and detail flows show current state, provenance, archive/restore, stale/conflict recovery, and scope-safe navigation. No writable graph/timeline editor appears in MVP.
- Prep is a Sanctum workflow. It autosaves GM input, keeps generated material non-canon until the owning acceptance path, presents citations/insufficiency, preserves local recovery, and exposes an explicit Ready for Stage handoff.
- Approval Queue is the trust surface: inspect source/version context, diff/edit, approve/reject/merge/archive one or selected compatible items, recover from conflicts, and show exact outcomes. Approval is the canon boundary.
- Import and attachment states show validating/uploading/extracting/ready/rejected/retry/provenance states. They never imply automatic AI, retrieval, embedding, or canon. Image-related Loom copy says it uses the GM-authored description and has not inspected pixels.
- Every core route needs meaningful loading, empty, denied, missing, archived, quota, offline, stale, provider-failure, and retry states. Preserve input and return focus after dialogs/sheets. Keyboard, reduced-motion, zoom/text scaling, and narrow responsive layouts are release requirements.

## Platform boundary

Responsive web on desktop, tablet, and phone browsers is the private-alpha client. Mobile uses equivalent workflows with sheets/stacks and larger targets, not a reduced product. Native Expo and push are deferred. See [[05 - Deferred Decisions]] and [[40 - Delivery Status]].
